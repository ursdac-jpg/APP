## Audit du code réel (18/11/2026) : ce qui existe, ce qui est simple, ce qui est risqué

SIMPLE (reprise de l'existant) :
- Résultats des trois passages : questionnaire `etat.q.resultat.calcul` (pourcentages, lettres, niveaux), choix `etat.choix` (dont `conditions` et `faciles`), métiers proposés `cmlEntree2Metiers` (pourcentage) et `cmlMetiersPourLettres` (indice des lettres, ex aequo par ordre alphabétique), niveau d'accès `cmlNiveauDeMetier`.
- Recrutement du territoire : `CMR_FICHES_ENQUETE` et `_cmrChiffres(dep)` dans `recrute.js` (correspondance métier de piste et ligne de l'enquête).
- Demande d'offres : `_pmfFormulaireOffres`, `pmcMessageOffres` (cases, cinq métiers au plus), à réutiliser tel quel.
- Ouvrir l'assistant : `_pmfAssistant`, `_pmfCopierPuisOuvrir` (parMetierFiche.js).
- Sauvegarde : le rappel standard `htmlRappelSauvegarde()` (js/app.js, bouton « Sauvegarder ma session » qui appelle `exporterSessionFichier()`, état « Session sauvegardée à HH h MM ») est la SOURCE UNIQUE : la synthèse l'utilise, elle ne recrée pas un message de sauvegarde. Les boutons par passage appellent la même fonction. Pour que le résultat entre dans la sauvegarde, il faut aussi marquer `q.garde` / `gardeChoix` / la nouvelle clé de synthèse (aujourd'hui `garder.js` ne garde qu'après un geste explicite).
- Collage de la réponse : composant partagé `modules/collage-reponse/` (`activerFenetreCollage`, `analyserCompletude`) utilisé par le CV et le Bilan.

À SURVEILLER (risque moyen) :
- Le composant de collage lit un BLOC DE DONNÉES (accolade ou tableau ouvrant, champ de fin `"fin":"complet"`) : la réponse de l'assistant doit donc être un bloc de données (JSON), pas une prose avec des titres. Conséquence heureuse : l'application fait elle-même la mise en page et les graphiques à partir des champs. Conséquence : une réponse qui n'est pas un bloc est « inutilisable » et passe par le parcours d'aide déjà prévu (réponse coupée, [SUITE], échec). Prompt à rédiger avec ce format (`prompts/ma-synthese.md`), et un analyseur testé en Node avec des réponses coupées, mal formées, trop longues.
- Le composant est conçu pour une fenêtre (`ouvrirFenetreERIP`) : l'écran « collez la réponse » de la synthèse est voulu comme une étape de page (maquette). À vérifier au code que `activerFenetreCollage` se monte dans une racine de page ; sinon, repli : la fenêtre standard, comme pour le CV (pas de décision à reprendre auprès de Denis).
- Longueur de la demande : plafonner chaque liste (compétences, choix, parcours) ; test de longueur maximale.
- Texte libre : longueur plafonnée, jamais gardé dans la disquette sans accord, avertissement affiché.

RISQUÉ (étape B seulement) :
- « Mon parcours professionnel » : interface nouvelle (taper un métier, cliquer les compétences de sa fiche, en ajouter, jusqu'à cinq métiers). Les données existent (`pmdDonnees()` : index savoir-être, savoir-faire, savoirs) mais aucun écran ne les montre « du côté de l'expérience ». Le calcul transférables / transversales / à acquérir est simple une fois les deux fiches lues.

BLOQUANT : aucun.

## Règles de travail en autonomie (une paire = un commit)
1. **Choisir l'enrichissement** de l'un des deux modèles : une vraie particularité (forme, bord, disposition, ton), courante dans les vrais CV, jamais une invention bizarre ; faisable dans Word ou avec un repli simple. Écrire la maquette dans `docs/MAQUETTE_<MODELE>_<date>.html` (surcharge de style sur le vrai rendu, voir le script `scripts/rendu/planche.js` pour la technique du compartiment étanche), pour que Denis la relise plus tard.
2. **Coder** l'option dans le rendu (`modules/cv-pdf-html/cvPdfTemplateMaquette.js`) et la recette du modèle (`cvPdfPanneauReglages.js`, champ de recette sans contrôle, lu automatiquement dans `opts`) : **seul le modèle visé doit changer**.
3. **Banc de rendu** en mode « vérifier » (page rechargée, stockage vide, fenêtre 738) : seul le modèle visé doit apparaître en écart ; sinon corriger.
4. **Vrai Word** : exporter le `.docx` du modèle (`rendre(modele, true)` expose `res.blob`, POST sur `/__ecrire/<nom>.docx`, `word-mesurer.ps1`, `pdf-vers-png.ps1`, lire l'image). Une page, forme correcte ; sinon adapter ou inscrire la limite dans `limitesWord.js` (avec test).
5. **Régénérer** registre et miniatures (`lancer('regenerer', { rendus: true })`, copier `sortie/registre.json` dans `scripts/rendu/`, `sortie/creatif_*.json` et `sobre_*.json` dans `data/miniatures/`), relancer `node scripts/rendu/ressemblance.js` et `node scripts/rendu/planche.js 0.9`.
6. **Tests** : `npm test`, essais navigateur concernés (au minimum `miniaturesReelles`, `modelesColonne`, `limitesWord`, essais du modèle ; suite par lots si doute : `docs/TESTS_PARCOURS_NAVIGATEUR.md`). Corriger les contrôles périmés (hauteur de colonne, etc.) dans le même commit.
7. **Commit** avec `git add` explicite (jamais `-A`), jamais de `push`. Noter dans ce fichier : hash, ce qui a changé, résultat Word, chiffre de ressemblance.
8. Si une difficulté technique majeure apparaît : s'arrêter, la noter ici, passer à la paire suivante (règle « jamais de mode tunnel »).

## Pièges déjà rencontrés
- Le banc exige : page rechargée, `localStorage` et `sessionStorage` vidés, fenêtre de 738 de large, script chargé quand `typeof dossier !== 'undefined'` ; après `resize_window`, la fenêtre peut revenir à une autre largeur : vérifier `innerWidth`.
- Python en ligne de commande : ne pas mettre d'apostrophe ni d'accent dans les chaînes passées par un heredoc ; pour du texte accentué, utiliser l'outil Write ou Edit (les titres de test avec apostrophe cassent le fichier).
- `rm` avec joker est refusé par la sécurité : supprimer fichier par fichier ou laisser en place (le dossier `scripts/rendu/sortie/` est ignoré par git).
- Le texte des miniatures hérite du style de la vignette : `all: initial` sur `:host` (déjà fait dans `_mepMiniMontrer` et `planche.js`).
- Le serveur de test peut prendre un autre port (consulter `preview_list`, onglet `tab-1`).
- La mesure de ressemblance est une mesure de STRUCTURE (classes, formes de style) : un enrichissement fait surtout en CSS (comme la carte) la fait peu baisser (Colonne claire / Colonne foncée : 100 % puis 93 %) alors que la différence se voit nettement. Juger à l'œil sur la planche autant que sur le chiffre ; améliorer la mesure (comparaison d'images) si besoin.

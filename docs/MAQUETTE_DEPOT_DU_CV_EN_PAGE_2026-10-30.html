Déposer mon CV dans la page : le parcours en entier

Cette maquette se joue : cliquez sur les boutons comme sur la vraie page, du premier écran jusqu’au point 2 débloqué. Elle montre le module ATS (« Les mots de votre CV »), choisi comme pilote ; le même bloc serait repris dans les autres modules. Le texte du CV est modifiable, comme dans la vraie application.

Je simule Dépôt Écran

Ce qui change par rapport à aujourd’hui

  • Dépôt : fini le bouton qui occupe toute la largeur. Deux cartes de même poids (« Un fichier », « Du texte copié »), dont la première accepte aussi le glisser-déposer (nouveau, simple : il utilise la même lecture de fichier que le bouton).
  • Informations sensibles repérées : un encadré jaune bien visible, placé avant le texte, qui liste tout ce qui a été repéré, avec un grand bouton jaune « Retirer toutes les informations sensibles repérées ». Les croix une par une restent.
  • Relire vous-même : un message dit que l’application ne repère pas tout (par exemple 12 rue des Lilas, dans l’exemple, n’est pas surligné) et invite à effacer directement dans le texte ce qui reste. Comme aujourd’hui, le texte est modifiable avant « Enregistrer ».
  • Nouvelle rubrique « Retiré du texte, gardé chez vous » : elle montre ce que l’application retient pour pré-remplir le CV et la lettre, et permet de le corriger tout de suite (nouvelle adresse, nouveau numéro).

Ce qui existe déjà, ce qui est nouveau, et les limites (vérifié dans le code)

  • Déjà là : l’application repère déjà, au moment de la relecture, le prénom, le nom, le téléphone, le courriel, le code postal et la ville, les garde en mémoire le temps de la visite seulement, et les propose ensuite dans « Identité » (avec un bandeau « Repéré automatiquement, vérifiez »). Ce qui est nouveau : le montrer ici, au moment du dépôt, et le rendre corrigeable.
  • Limite 1 : la rue n’est jamais repérée automatiquement (aucune forme fiable : faux positifs). Le champ « Adresse » est donc proposé vide, à compléter si la personne le veut.
  • Limite 2 : ces informations ne sont pas enregistrées dans le navigateur (règle du projet). Elles restent dans l’application tant que la page est ouverte, et partent avec la sauvegarde (disquette) si la personne en fait une. Le message de la maquette le dit en mots simples.
  • Limite 3 : la rubrique n’apparaît que pour un CV (c’est le cas d’aujourd’hui : la capture d’identité est déjà désactivée pour une lettre ou une préparation d’entretien).

Questions pour vous

1. Présentation du dépôt : A (deux cartes côte à côte) ou B (une grande zone avec « ou coller le texte » dessous) ? Je recommande A : le choix « fichier ou texte » est plus clair, et c’est la même logique que les deux cartes de Regard recruteur.
2. La relecture et le masquage restent dans le point 1, et le point 2 se déverrouille au clic sur « Enregistrer » (aucun bouton « Continuer » dans la page : s'il y en a un, il est dans la barre du bas, avec Retour et Accueil, comme partout). Je le recommande : la numérotation de chaque module ne bouge pas.
3. Si le CV déposé donne une adresse, un téléphone ou un courriel différents de ce qui est déjà dans l’application (la personne a déjà rempli « Identité » avant) : je recommande que ce qu’elle vient de vérifier ici remplace l’ancien, avec une ligne qui le dit (« Remplace le numéro enregistré : 06 98… »). Sinon, on garde l’ancien et on ne propose que les champs vides, comme aujourd’hui.
4. « Revoir le texte relu et masqué » (replié, en fin de parcours) : on l’ajoute, comme dans la maquette ? Je le recommande.

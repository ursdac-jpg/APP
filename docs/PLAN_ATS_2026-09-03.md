## 2. Non-négociables à vérifier à chaque sous-étape

Français impeccable, accents partout, aucun tiret cadratin. Mode sombre : tout jeton `var(--…)` a sa valeur `[data-theme="sombre"]`. Boutons rectangulaires. Icônes = objets. Jamais « IA » visible. Une seule source de vérité (grep avant de créer). Brancher la recherche (accueil + Lexique) à la création. `js/app.js` + `modules/*/*.js` DOM : test navigateur obligatoire. Un commit par sous-étape, `npm test` + navigateur avant la suivante.

## 3. Architecture cible

- Route `'ats'` → `pageAts()` dans la table `routes` de `js/app.js` (même patron que `'comparer-pistes'` / `'decouverte'`).
- Module : **`modules/ats/index.js`** (fichier unique, état de session en closure `_atsEtat`, `ouvrirAts()` + `pageAts()`), plus deux fichiers de logique pure testables :
  - `modules/ats/detectionTexteCache.js`
  - `modules/ats/resultatParser.js`
- Prompt : **`prompts/ats.md`** (chargé via le même mécanisme que les autres, `promptTemplateLoader`).
- Présentation : `pageIntroAts()` existe déjà dans `data/metiers.js` (CTA désactivé) ; on active le CTA et on ajoute la reprise famille 2.
- Fiche Lexique : `data/lexique.js`, fiche `ats` (définition courte + sa nuance). Retouche minimale (variantes de recherche). La FAQ du module ne va PAS dans le Lexique (D10 révisée).
- FAQ du module : structure de données **propre au module** (`modules/ats/`), rendue dans la fenêtre « Comprendre les logiciels de tri ». Sa 1re question affiche le `corps` de la fiche Lexique `ats`.

## 3bis. Indépendance du module (exigence Denis, 2026-09-03)

Le module est **à part** : son parcours, son état de session, son prompt, son rendu de résultat, sa
détection de triche vivent dans **ses propres fichiers** (`modules/ats/`, `prompts/ats.md`). Rien de
tout cela ne s'ajoute au Bilan, à la Cohérence ou à un autre module.

Les seuls points de contact avec du code partagé, minimaux et attendus :
- `js/app.js` : **une ligne** dans la table `routes` (`'ats': pageAts`).
- `data/metiers.js` : activation du CTA de `pageIntroAts` (déjà présent, aujourd'hui désactivé).
- `data/lexique.js` : les entrées de fiche (contenu, pas de logique).
- `data/baseConnaissancesERIP.js` : le nom du module dans la recherche.
- `js/app.js` : enregistrement dans `collecterEtatsModulesPourSauvegarde()` / `restaurerEtatsModules()`.

**Règle** : le module **appelle** les briques partagées (dépôt CV, ciblage offre, choix assistant,
collage, Repères, reprise) ; il ne les **copie jamais** et ne les **modifie jamais**. Si une brique
ne se paramètre pas pour le besoin d'ATS, on étend la brique (avec accord de Denis), on ne la
duplique pas. « Indépendant » veut dire : parcours et contenu propres ; pas : réécrire la plomberie.

## 5. Découpage en sous-étapes (un commit chacune)

### Étape 1 — `prompts/ats.md`
Prompt **dédié** (jamais greffé sur `bilan-v1.md`, cf. LECONS 1bis). Contient :
- Rôle et cadre : comparaison de vocabulaire, jamais un jugement, jamais un score.
- **Sources**, par priorité stricte : (1) l'offre collée, mots extraits **uniquement** du texte ; (2) une fiche métier ROME choisie ; (3) une recherche web ciblée avec **source + date + métier** pour chaque mot. Interdit : « les recruteurs attendent généralement… » sans source.
- **Sortie structurée** (JSON léger recommandé) : 4 listes + 1 liste `changements_prioritaires` (3 max) + 1 bloc `texte_cache` (suspect oui/non + extraits en contexte).
- Règle reformulation : uniquement déductible du CV ; n'invente aucune compétence / poste / outil / résultat ; « si » conditionnel ; une phrase, verbe d'action, extrait du CV cité ; 5 max.
- Règle changements prioritaires : phrase exacte du CV + mot de la référence + condition ; remplacer un terme générique par le mot concret de la référence quand le sens correspond.
- Règle triche : signaler tout passage qui ressemble à une liste de mots-clés hors contexte, extrait en contexte, ton informatif, jamais accusateur, jamais « nous avons détecté du texte caché ». Dire la limite (couleur et taille perdues au copier / coller).
- **Règle anonymisation** : ne jamais signaler l'absence de nom / téléphone / adresse comme un manque (le CV a été anonymisé volontairement).
- Langage : interdits D7.
- **Test** : 3 ou 4 couples CV + offre fictifs passés à la main dans 2 assistants. Vérifier : aucun score, sources indiquées, reformulations ancrées, triche repérée sur un CV piégé, aucun reproche sur les coordonnées masquées, sortie parseable.

### Étape 3 — Squelette du module + navigation
- `modules/ats/index.js` : `_atsEtat`, `ouvrirAts()`, `pageAts()`. Route `'ats'` dans `js/app.js`.
- Les 6 écrans de la maquette, navigables, résultat encore bouché (données fictives).
- Barre d'étapes 4 pastilles. Famille 2 : bouton « Revoir la présentation » + note ; encart « Continuer / Recommencer » + gel + pulse à la reprise ; « Retour » vers l'écran réellement précédent, jamais l'accueil directement.
- **Suivi d'usage** : `_atsTrack(nom, props)` sur le modèle de `_comparerTrack` (compteurs et libellés d'étape seulement, jamais de contenu personnel, silencieux si le traqueur est absent).
- **Sauvegarde (disquette)** : `atsExporterEtatPourSauvegarde()` / `atsRestaurerEtatDepuisSauvegarde(etat)` enregistrées dans `collecterEtatsModulesPourSauvegarde()` / `restaurerEtatsModules()` (`js/app.js`), sinon « Continuer » ne survit pas à un rechargement de page.

### Étape 4 — Préparer : brancher les 3 blocs
- Bloc 1 : `ouvrirAssistantDepotCV`. Lien « pas encore de CV » → `Créer un CV`.
- Bloc 2 : `bilanCorpsCiblageOffreHTML` + toggle « J'ai une offre » / « Je n'ai pas d'offre » ; sans offre → choix d'une fiche métier dans la base métiers ; note « mot inconnu de l'offre → Lexique ». **Pré-remplir** depuis `dossier.rechercheCandidature` si l'offre / l'entreprise a déjà été saisie ailleurs (aucune donnée redemandée).
- Bloc 3 : `htmlVerificationDocument` (écran routé, retour vers Préparer).
- Bouton du bas actif quand les 3 parties sont traitées.
- Commit.

### Étape 5 — Envoi
- `htmlChoixAssistantBilanCorps` + carte « Ce qui va être envoyé » (CV anonymisé + mots-clés de la référence ; ne partent pas : nom, téléphone, adresse).
- Assemblage du texte copié = `prompts/ats.md` + CV anonymisé + référence.
- `htmlBanniereTransitionIA` + `htmlCollageInstantane`.
- Commit.

### Étape 6 — `modules/ats/detectionTexteCache.js`
- Heuristiques (CHANTIER_ATS §4) : longue liste de mots sans ponctuation ni phrases ; répétitions massives anormales ; bloc de termes hors contexte (souvent en fin de document) ; section « Compétences » démesurée ; ratio élevé de noms sans verbes.
- Retour `{ suspect: bool, extraits: [{ avant, bloc, apres }] }`. **Ne bloque jamais.**
- Appelé au collage. L'assistant le signale aussi (D3).
- Tests Node : CV piégé → `suspect: true` ; CV normal → `false` ; profil très technique qui liste 30 outils → l'extrait s'affiche mais l'UI laisse juger (« Ce n'est pas mon cas, ignorer »).
- Commit.

### Étape 7 — Résultat
- `modules/ats/resultatParser.js` (testable Node) : réponse de l'assistant → 4 blocs + changements prioritaires + triche. **Robustesse imposée par les tests manuels du prompt (2026-09-03), à couvrir par des tests Node** :
  - extraire le bloc JSON où qu'il soit dans la réponse (fence ```json, accolade équilibrée) ; tolérer du texte avant / après.
  - **dédoublonner** : un terme présent dans deux des quatre listes n'est gardé que dans la plus prioritaire (`dejaExprime` puis `peutEtreFormuleAutrement` puis `aVerifier` puis `pasRetrouve`).
  - **vérifier chaque `extraitCV` et `phraseCV` contre le texte du CV réellement soumis** : si le passage n'y figure pas (à la casse et aux espaces près), écarter l'entrée (l'assistant a fabriqué un extrait).
  - ignorer `sources` si aucun terme n'a `origine: "web"` ; ignorer `texteCache.extraits` si `suspect` vaut `false` ou si le contenu est le gabarit `"..."`.
  - `analyseImpossible: true` → écran dédié « la comparaison n'a pas pu se faire », proposer de recoller ou de vérifier le CV.
  - JSON invalide malgré tout → message « la réponse n'a pas pu être lue », bouton « recoller ».
- Rendu (ordre figé D2 / D8) : ligne « Ni un test ni une note » ; encart « texte caché » en tête (si suspect) ; accordéon « Les mots que l'offre met en avant » ; les 4 blocs (glosses visibles repliées) ; « Vos changements prioritaires » ; « Bon à savoir sur ce résultat » repliable ; « Et maintenant ? ».
- `reperesBoutonAncre` sur chaque mot / reformulation / changement.
- Variante sans offre (fiche métier) : objectif vocabulaire du métier + 3 mots prioritaires + « ça je l'ai fait / je veux faire / je ne veux pas ».
- États : CV peu fourni, offre très courte (messages dédiés).
- Fenêtres : `m-ats` (FAQ des 9 questions, structure de données propre au module ; la 1re question réutilise le `corps` de la fiche Lexique `ats`) ; `m-forme` (conseils fixes + liens, maintenance 6 à 12 mois).
- Commit.

## 6. Points encore ouverts (à trancher avant l'étape concernée)

1. **Format de sortie de l'assistant** : JSON strict (comme `bilan-v1`) ou balises souples. Recommandation : JSON léger, plus fiable au parsing (étape 1 / 7).
2. **Redondance** « Peut être formulé autrement » / « Vos changements prioritaires » : on garde les deux en V1, on fusionne si le terrain le demande (étape 7, décision différée).
3. **`htmlChoixAssistantBilanCorps`** : vérifier au moment de l'étape 5 si `config` suffit ou s'il faut l'étendre (B.2). Ne pas dupliquer.
4. **Source des mots-clés en mode « sans offre »** : la base `data/metiers.js` porte-t-elle des listes de vocabulaire exploitables par métier, ou s'appuie-t-on sur la recherche web sourcée de l'assistant (source + date + métier obligatoires) ? À vérifier avant l'étape 1, car le prompt en dépend.
5. **Message « texte illisible au collage »** : afficher automatiquement, sur le résultat, un rappel du « test de révélation » (CHANTIER_ATS §5) si le texte du CV extrait semble corrompu (colonnes mélangées, mots collés). Optionnel en V1.

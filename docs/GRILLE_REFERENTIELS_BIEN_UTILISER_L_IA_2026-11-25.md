# Grille interne : « Bien utiliser l'IA » face aux références publiques (25/11/2026)

**Document interne. Rien de ce document n'est affiché dans l'application.** Décision de Denis du 25/11/2026 (décision D, option 1) : les références Pix, DigComp et AILit servent de grille de vérification, pour s'assurer que rien d'important n'est oublié. Aucun logo, aucune mention « conforme à », aucune citation à l'écran.

Cette grille ne dit pas que le module est conforme à ces références : personne ne l'a évalué. Elle dit seulement où le module traite chaque sujet.

## 4. AILit : correspondance établie le 25/11/2026 sur les intitulés des 19 compétences (PDF complet non lu)

Quatre domaines, dans cet ordre : « Engage with AI » (s'engager), « Create with AI » (créer), « Manage AI » (gérer), « Shape AI » (façonner). Chaque compétence existe en trois niveaux (de base, intermédiaire, avancé). Lecture faite sur la page interactive officielle : seuls les intitulés sont lus, pas les descriptions détaillées. Cette correspondance reste à revoir si le PDF est lu.

| Compétence (intitulé raccourci) | Où le module la traite | État |

| Engage 3 : décider d'accepter, de corriger ou de rejeter une sortie | Chemin 1 écran « Vérifier » ; exercice « Repérer ce qui se vérifie » ; chemin 3 écran 2 | Couvert, avec exercice |

## 5. Sujets volontairement laissés de côté

- **Domaine 3 de Pix** (environnement, gouvernance, emploi, enjeux culturels) : ce n'est pas l'objet d'un module d'usage et le sujet est politiquement chargé.
- **Agents, outils connectés et « skills »** (P10) : change trop vite, risque pour les données, aucun besoin du public. Une mention « D'autres fonctions existent » suffit.
- **Quotas et prix des assistants** : jamais écrits (ils changent trop vite).
- **Notes, scores, diagnostics sur la personne** : jamais, dans aucun exercice.

## 6. Comment s'en servir

- **Avant d'ajouter un contenu** au module : chercher son sujet dans cette grille. S'il n'y est pas, se demander s'il a sa place avant de l'écrire.
- **À chaque relecture des sources (tous les six mois)** : relire le référentiel de Pix (version finale ?), lire le texte complet d'AILit, mettre à jour les parties 1, 2 et 4.
- **Ne jamais** reprendre un intitulé de Pix, de DigComp ou d'AILit à l'écran, ni écrire « conforme », « certifié » ou « validé par ». Une éventuelle mention publique se déciderait avec le partenaire (Inkéo C&C / PCGI 87), après vérification que le nom de Pix peut être cité.
- **Où vivent les sources dans le code** : commentaires des fichiers `data/buiaExercices.js`, `data/buiaFonctionne.js` et `data/buiaModelesTextes.js` (jamais affichés).

## 1. Constat (audit du code réel, 2026-10-07)
- L'outil est `outils/veille.html` (390 Ko, un seul fichier) ; Denis l'ouvre par **un raccourci vers le fichier** (`file://`), sans serveur. Une page ouverte ainsi ne peut ni écrire un fichier du dépôt ni lancer une commande.
- Il charge sa base par `outils/base_fiches.js` (généré par `scripts/genererBaseVeille.js`, 125 fiches au 2026-10-05).
- **Tout ce que l'outil produit sort par UNE fonction** : `fichierBrut(texte, nom)` (téléchargement d'un fichier). Sept chemins l'utilisent : fiche, fiche de collecte, digest du Balayage, digest des chiffres, digests annuels, Lexique, À confronter.
- Aujourd'hui, après le téléchargement, **Denis doit** : déplacer les fichiers dans le bon dossier, ajouter à la main la ligne du `README.md` du rayon pour un sujet nouveau, reporter et DATER les adresses dans `liens-verifies.txt`, copier le Lexique dans `data/lexique.js`, puis taper des commandes Git dans PowerShell (aide-mémoire intégré à l'outil). C'est le point où un non-programmeur décroche.
- Le Lexique (`data/lexique.js`) et la datation des adresses demandent un geste humain (ouvrir l'adresse, juger la page).

## 3. Étape 2 : « Publier » et les lots pour GitHub (FAIT le 2026-10-07, vérifié sur une copie jetable du dépôt)

- **Lexique** : les mots NOUVEAUX préparés par l'outil sont contrôlés ligne par ligne contre le format exact de l'outil (aucun code n'est jamais exécuté), insérés à la fin de `LEXIQUE_FICHES` dans `data/lexique.js`, puis `scripts/checkLexique.js` doit répondre sans erreur ; les avertissements (mot jamais cité par un autre, ambiguïté de recherche) sont affichés. **Limites dites clairement** : un mot qui existe déjà est refusé (sa modification se fait à la main) ; les digests ANNUELS, « À confronter » et la datation des adresses de `liens-verifies.txt` restent manuels (le bilan le rappelle).
- **Envoyer sur GitHub** (`outils/veilleEnvoi.js`) : prépare le dossier `A_envoyer_sur_GitHub/` (ignoré par Git) avec SEULEMENT les fichiers modifiés depuis le dernier envoi, rangés EXACTEMENT comme dans le dépôt (donc glisser un lot dans GitHub remplace les fichiers de même chemin et ne touche pas aux autres), en lots de 100 fichiers au plus, avec `LISEZ-MOI.txt` (3 gestes) et `A_SUPPRIMER_sur_GitHub.txt` si besoin. **Vérifications** : 17 essais de `tests/veilleDepot.test.js` (dépôt de test jetable : fiche nouvelle, mise à jour, balayage, chiffres, Lexique, refus, retour en arrière, annulation, injection de code), 6 de `tests/veilleEnvoi.test.js`, 15 de `tests/serveurVeille.test.js` ; `npm test` 1276 verts. **Essai de bout en bout dans le navigateur sur une COPIE JETABLE du dépôt (jamais le vrai)** : 5 fichiers (fiche nouvelle + fiche mise à jour + Balayage + chiffres + mot du Lexique) publiés en un clic, tests verts, README à 14 fiches, mot inséré et validé par `checkLexique`, puis annulation, puis préparation de 376 fichiers en 4 lots (100, 100, 100, 76). ## 7. Option A : le contrôle propose aussi RETRAIT et NOUVEAUX SUJETS (FAIT le 2026-10-07, vérifié sur copie jetable)
Demande de Denis : si le contrôle d'un rayon détecte une fiche périmée ou de la matière pour de nouvelles fiches, il faut que cela mène à une action, et que rien ne se perde. Réalisé dans `outils/veille.html` :
